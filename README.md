# fractal

Терминальный скринсейвер с фракталами: не «рисовалка Мандельброта», а небольшой
движок, который сам летает по красивым местам комплексной плоскости, плавно
меняет палитры и умеет сохранять кадры в PNG.

Пять фракталов, десять палитр, многопоточный расчёт, TrueColor, суперсэмплинг и
автоматический поиск новых интересных областей. Из зависимостей — только
`crossterm` для работы с терминалом и `serde` для чтения конфигов.

## Быстрый старт

```bash
cargo run --release
```

Без аргументов включается автопилот: камера облетает точки из
`assets/cameras.json`, иногда сворачивая в места, которые находит сама.

Полезные варианты запуска:

```bash
cargo run --release -- --fractal burning_ship --supersample 2
```

```bash
cargo run --release -- --at -0.743643887037151,0.13182590420533,3e-4 --no-autopilot
```

## Управление

| Клавиши | Действие |
| --- | --- |
| `W` `A` `S` `D`, стрелки | сдвиг камеры |
| `+` / `-`, PgUp / PgDn | приблизить / отдалить |
| `E` / `R` | поворот кадра |
| `Tab` / `Shift+Tab` | следующий / предыдущий фрактал |
| `P` / `Shift+P` | следующая / предыдущая палитра |
| `N` | следующая точка из `cameras.json` |
| `F` | найти интересное место рядом |
| `Space` | автопилот ↔ ручное управление |
| `X` | суперсэмплинг 1× → 2×2 → 3×3 |
| `T` | TrueColor ↔ 256 цветов |
| `[` / `]` | бюджет итераций меньше / больше |
| `O` | сохранить кадр в PNG |
| `F1`, `H` | показать/спрятать статистику |
| `L` | перерисовать экран целиком |
| `Shift+R`, `0` | вернуться в исходную точку |
| `Esc`, `Q`, `Ctrl+C` | выход |

Любое движение камеры автоматически выключает автопилот; `Space` возвращает его.

## Аргументы командной строки

```
-c, --config <ФАЙЛ>    файл настроек (по умолчанию config.toml)
-f, --fractal <ID>     mandelbrot | julia | burning_ship | tricorn | newton
-p, --palette <ИМЯ>    имя палитры из palettes.json
    --at <X,Y,ZOOM>    начальная точка обзора
    --fps <N>          ограничение частоты кадров (0 — без ограничения)
-j, --threads <N>      число потоков (0 — по числу ядер)
-s, --supersample <N>  сглаживание N×N (1..4)
    --no-autopilot     не летать самому
    --no-hud           спрятать статистику
    --no-truecolor     использовать 256 цветов вместо 24-битных
    --record <КАТАЛОГ> писать кадры в PNG (медленно, для видео)
    --frames <N>       выйти после N кадров
-h, --help             справка
```

Приоритет: аргументы → `config.toml` → значения по умолчанию. Отсутствующий
`config.toml` не ошибка.


## Как всё устроено

**Фракталы — это плагины.** Каждый реализует один трейт:

```rust
pub trait Fractal: Send + Sync {
    fn id(&self) -> &'static str;
    fn name(&self) -> &'static str;
    fn sample(&self, x: f64, y: f64) -> Pixel;
    fn home(&self) -> Home;
    // …бюджет итераций, анимация параметров, строка для HUD
}
```

`Pixel` несёт три вещи: попала ли точка внутрь множества, сглаженное число
итераций и дополнительный канал (у Ньютона в нём лежит номер корня). Всё
остальное — раскраску, символы, сглаживание — делает рендерер, поэтому новый
фрактал добавляется файлом рядом и одной строкой в `fractals::all()`.

**Расчёт распараллелен по полосам.** Стоимость строки различается на порядки:
строка по «телу» множества считает все итерации, строка по фону вылетает за
пару. Поэтому полос делается вчетверо больше, чем потоков, и потоки разбирают
их из общей очереди — это балансировка нагрузки без планировщика.

**Вывод идёт диффом.** Рендерер держит два буфера знакомест и печатает только
изменившиеся, экономя и перестановки курсора, и коды цвета.

**Цвет.** Палитра — 256 цветов, растянутых из опорных точек. Номер итерации
проходит через треугольную волну, поэтому цветовые полосы стыкуются без разрыва
даже у палитр, у которых начало и конец разного цвета. Символ выбирается по
яркости получившегося цвета: тёмное получает точки и запятые, яркое — сплошную
заливку, отсюда эффект свечения.

**Полёты не линейные.** Зум интерполируется логарифмически, а положение
привязано к `1/zoom`: цель быстро оказывается в центре кадра, дальше идёт чистое
погружение. Без этого камера «пролетает» все интересные масштабы за первые кадры.

**Разведчик** (`scout.rs`) бросает случайные точки в текущий кадр, оценивает
разброс числа итераций в окрестности каждой и сужает область вокруг лучшей.
Несколько шагов — и камера стоит над границей множества на глубине, которую
никто заранее не размечал.

## Свои палитры и точки

`assets/palettes.json` — имя и опорные цвета, которые растягиваются на 256
позиций:

```json
{ "fire": [[0,0,0],[122,15,0],[255,140,0],[255,251,224]] }
```

`assets/cameras.json` — список точек. `zoom` это половина ширины кадра в
единицах комплексной плоскости, поэтому меньшее значение = более глубокое
погружение. Поля `hold` и `flight` необязательны:

```json
{
  "fractal": "mandelbrot",
  "name": "Seahorse Valley",
  "x": -0.743643887037151,
  "y": 0.13182590420533,
  "zoom": 0.00035,
  "hold": 8.0
}
```

Оба файла вшиты в бинарник как запасной вариант, так что программа работает и
без каталога `assets/`. Чтобы всегда использовать встроенные наборы, оставьте
`palettes_path` и `cameras_path` пустыми.

## Экспорт кадров

`O` сохраняет текущий вид в PNG (размер задаёт `export_width`, пропорции берутся
от видимой области, а не от сетки знакомест). `--record <КАТАЛОГ>` пишет каждый
кадр — из полученной последовательности собирается видео:

```bash
ffmpeg -framerate 30 -i frames/mandelbrot-%06d.png -c:v libx264 -pix_fmt yuv420p out.mp4
```

Кодировщик PNG написан вручную и использует несжатые блоки deflate: файлы
получаются крупнее обычных, зато проект остаётся без графических зависимостей.

## Ограничения

* Глубина зума упирается в точность `f64` — примерно `1e-14` по ширине кадра.
  Дальше картинка распадается на ступеньки, и HUD об этом предупреждает.
  Для более глубоких погружений нужна арифметика с возмущением (perturbation).
* Рампа по умолчанию содержит `█`; если шрифт терминала его не рисует, задайте
  `char_ramp` без последнего символа.
* Мышь не используется — скринсейверу она ни к чему.

## Тесты

```bash
cargo test
```

Кроме математики фракталов и утилит проверяются вещи, которые ломаются молча:
пул потоков обходит каждую строку ровно один раз, PNG сходится по CRC и Adler32,
а каждая точка из `cameras.json` действительно показывает структуру, а не
однородную заливку.
